# Monkey 批次测试 - 体验优化思路

目标：让人用的时候感觉**顺手、方便**，而不是「能跑但很绕」。

---

## 一、原则

1. **一个地方做完一件事**  
   想跑批次 = 在批次页填设备、点启动就完事。不要「先去首页连好再回来」。

2. **少让用户做决定**  
   端口、格式尽量自动处理；只填 IP 或从列表选，其余用合理默认。

3. **每一步都有反馈**  
   正在连、正在起 Monkey、哪台成功/失败，都要能看见，不等、不猜。

4. **出错能自己救**  
   失败时说明原因 + 建议（如「设备未开调试」「换 5555 试」），而不是「请到控制面板」。

---

## 二、批次页怎么改才顺手

### 1. 连接和启动合成一条龙

- **当前**：要先在首页「连接」设备，再到批次页填列表、启动。
- **目标**：在批次页填 IP（或选「已连接设备」）→ 点「启动批次」→ 后端自动尝试连接未连上的设备（先试 5555，再试 8787），连上再起 Monkey。
- **体验**：用户只做「填/选设备 + 点启动」，不关心「先去哪连」。

### 2. 端口别让人操心

- **当前**：默认 8787，很多设备是 5555，连不上就要自己去首页试端口。
- **目标**：只填 IP 时，后端按顺序试 5555、8787（可配置），连上哪个用哪个；或记住某 IP 上次成功端口下次优先用。
- **体验**：用户只写 `192.168.16.131` 就行，不纠结端口号。

### 3. 状态一眼能看懂

- **当前**：「已启动」只代表协调器没报错，实际 Monkey 可能没跑起来或已挂，看不出来。
- **目标**：每台设备有明确状态，例如：`连接中` → `Monkey 运行中` → `已完成` / `失败`；失败时给一句原因（如「设备无响应」「包名未安装」）。
- **体验**：扫一眼就知道「哪台在跑、哪台挂了、为什么挂」。

### 4. 实时日志说人话

- **当前**：有日志，但「成功」要看到 PID 才踏实，连接失败时原因不够直白。
- **目标**：  
  - 连接：`正在连接 192.168.16.131（试 5555）…` → `已连接` 或 `连接失败：超时，请检查设备网络与调试`。  
  - Monkey：`192.168.16.131 Monkey 已启动 PID: xxx` 或 `192.168.16.131 启动失败：包名未安装`。  
- **体验**：不用猜、不用切到别的地方查。

### 5. 设备列表和首页统一

- **当前**：批次页「从上选择」= 当前已连接设备，若没在首页连过就是空的。
- **目标**：同一套「已连接设备」来源；在批次页点「刷新设备」= 拉当前 adb 列表，可选多台一键填入；支持「只填 IP」由后端自动连。
- **体验**：首页连过的设备在批次页直接可选；没连过的填 IP 也能在批次里一次搞定。

### 6. 失败时给可执行建议

- **当前**：失败常提示「请先在控制面板连接设备」，用户不知道具体错在哪。
- **目标**：根据错误类型返回简短说明 + 建议，例如：  
  - 连接超时 → 「请确认设备与电脑同一网段、已开启 USB 调试（网络）」。  
  - 连接被拒 → 「试一下端口 5555 或 8787」。  
  - 包名不存在 → 「请确认设备已安装该应用」。  
- **体验**：按提示就能排查，不用翻文档或问人。

---

## 三、可选的「更顺手」增强

- **记住上次**：记住上次用的设备列表、包名、事件数，下次打开预填。
- **快捷入口**：仪表盘或首页放「批量 Monkey」入口，点进去就是批次页，减少找入口的步骤。
- **批量连接按钮**：在批次页提供「批量连接」（输入 IP 段或列表），只做连接、不启动，连接结果在列表里标出来，再点「启动批次」。
- **简单/高级模式**：默认只展示「设备 + 包名 + 启动」，轮数、采样间隔等收在「高级选项」里，需要再展开。

---

## 四、小结

核心就是：**少步骤、少纠结、多反馈、出错能自救**。  
改的时候优先做「连接+启动一条龙」「端口自动试」「状态和日志说人话」，再做记住上次、快捷入口等，用起来就会明显更顺手、方便。
