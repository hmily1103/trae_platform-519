# 优化建议与现状对照

基于对当前代码库的扫描，对以下优化点进行**逐一验证**，并标注已落地 / 待优化 / 优先级。

---

## 1. 架构与代码质量

### 1.1 ADB 客户端统一 (Unified Device Manager)

**现状验证**：✅ **属实**，存在多套 ADB 实现：

| 实现 | 位置 | 用途 |
|------|------|------|
| `AdbHelper` | `utils/adb_helper.py` | 平台级：设备列表、连接/断开 |
| `AdbController` | `modules/log_monitor/core/adb_controller.py` | 日志监控、logcat |
| `AdbManager` | `modules/player_stress/core/adb_manager.py` | 播放器压测、shell 执行 |
| `DeviceController` | `modules/ui_automation/core/device_controller.py` | UI 自动化、uiautomator |
| `RemoteDeviceController` | `modules/remote_control/core/device_controller.py` | 远程控制、scrcpy |

- `performance_monitor` 复用 `log_monitor.AdbController`
- `rk_collector.py` 中有注释：*「临时适配，理想情况下 AdbController 应该提供通用接口」*

**建议**：抽象平台级 `DeviceManager`，统一连接、命令执行、重试与错误处理。  
**优先级**：高（减少重复、避免连接冲突）

---

### 1.2 配置中心化 (Centralized Configuration)

**现状验证**：✅ **部分属实**，配置分散：

| 配置来源 | 位置 | 说明 |
|----------|------|------|
| `config_loader.py` | `utils/` | 已统一：announcements、song_order（环境变量） |
| `config.json` | `modules/reboot/` | 重启模块 |
| `config.json` | `modules/player_stress/` | 播放器压测 |
| `config.json` | `modules/sanfang/` | 硬编码路径 |
| `llm_config.json` | `modules/test_case/` | 用例管理 LLM |
| `config.json` | `modules/monkey/` | 硬编码路径 |

**建议**：引入统一 `ConfigManager`，支持从统一配置源加载并热更新。  
**优先级**：中（已有 `config_loader` 基础，可逐步迁移）

---

## 2. 稳定性与可靠性

### 2.1 运行时持久化 (Runtime Persistence)

**现状验证**：✅ **属实**

- `core/runtime/manager.py`：`_runtimes: Dict[str, RuntimeObject]` 纯内存
- 平台重启后，Runtime 状态全部丢失
- `shared/unified/report_store.py` 已做**报告持久化**（JSON 磁盘），但 Runtime 生命周期仍只在内存

**建议**：用 SQLite 或 Redis 持久化 Runtime 状态，支持重启后恢复与历史回溯。  
**优先级**：高（与任务可追溯性直接相关）

---

### 2.2 资源锁与冲突管理 (Resource Locking)

**现状验证**：⚠️ **部分存在**

- Monkey、UI 自动化等可能同时操作同一设备
- 无显式设备占用锁或冲突检测
- 部分模块内部有锁（如 `monkey_tests_lock`），但无跨模块协调

**建议**：在 Runtime 层增加设备级资源锁，占用设备时阻止冲突任务启动。  
**优先级**：中（依赖 ADB 统一后更易实现）

---

## 3. 用户体验与功能

### 3.1 统一任务看板 (Unified Task Dashboard)

**现状验证**：⚠️ **部分已实现**

| 已有能力 | 说明 |
|----------|------|
| `/unified/` 一键任务 | 编排 Monkey + 性能 + 日志 + UI 套件 + ARM 压测，一次启动 |
| `/runtime_center/` 运行中心 | 展示 Runtime 列表（来自内存），可按 module/status 筛选 |
| `/unified/reports` 报告中心 | 统一报告列表，支持筛选 |

**差距**：  
- 运行中心依赖内存 Runtime，重启后为空  
- 一键任务侧重编排，不是「全局任务看板」  
- 各模块任务仍需到各自页面启动（Monkey、PlayerStress 等）

**建议**：在 Runtime 持久化基础上，做强「运行中心」为全局任务看板。  
**优先级**：中（依赖 Runtime 持久化）

---

### 3.2 标准化报告 (TROM)

**现状验证**：✅ **已部分落地**

| 已有能力 | 说明 |
|----------|------|
| `shared/unified/report_store.py` | 统一报告存储，JSON 格式 |
| `save_report()` | Monkey、UI 自动化、Unified 等已接入 |
| `list_reports()` | 支持 module、kind、status、keyword 筛选 |
| `shared/core/trom.py` | TROM 模型（TaskType、StreamSource、BehaviorItem 等） |

**差距**：  
- 部分模块（如 reboot、player_stress）仍用自有报告格式  
- 报告结构已统一，但未强制所有模块接入

**建议**：推动剩余模块接入 `report_store`，统一报告结构。  
**优先级**：低（主流程已覆盖）

---

## 4. 部署与运维

### 4.1 容器化部署 (Dockerization)

**现状验证**：✅ **属实**，当前无容器化

- 无 `Dockerfile`、`docker-compose.yml`
- 依赖本地 Python、ADB、Scrcpy 等环境

**建议**：提供 `Dockerfile` 和 `docker-compose.yml`，一键拉起完整环境。  
**优先级**：中（提升部署与复现能力）

---

## 5. 优先级建议（更新）

结合现状与依赖关系，建议实施顺序：

| 优先级 | 优化项 | 理由 | 状态 |
|--------|--------|------|------|
| **P0** | Runtime 持久化 | 运行中心、任务回溯的基础 | ✅ 已落地（SQLite） |
| **P1** | ADB 统一 | 减少重复、降低冲突风险 | ✅ 已落地（core/device/DeviceManager） |
| **P2** | 统一任务看板增强 | 依赖 Runtime 持久化 | ✅ 已落地（运行中心增强） |
| **P2** | 资源锁 | 依赖 ADB 统一 | ✅ 已落地（DeviceManager.acquire/release） |
| **P3** | 配置中心化 | 已有 config_loader，可渐进迁移 | ✅ 已落地（get_platform_config） |
| **P3** | Docker 部署 | 独立于业务逻辑 | ✅ 已落地（Dockerfile + docker-compose） |
| **P4** | TROM 全模块接入 | 主流程已覆盖 | 待渐进迁移 |

---

## 6. 总结

- 上述优化点均**有效**，与代码库现状一致。  
- 部分能力已有基础：报告统一、config_loader、运行中心、一键任务。  
- 建议优先推进 **Runtime 持久化** 和 **ADB 统一**，再逐步完善任务看板和资源锁。  
- 当前功能已闭环，可先以业务使用为主，再按优先级分批优化。
