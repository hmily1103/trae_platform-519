## 8. 项目启动红线（准入准则）— **已定：条文放 L1，缺口放 L3**

**原则**：红线条文是**治理/开工门槛**，与「打回/限制/准予」强绑定，**不单独放在 L2**（L2 是 PM/PO 澄清与方案选择，不是排期政策）。L3 承载**具体是否满足**红线的**证据与缺口**。

| 红线（摘要） | L1 中写什么 | L3 中落什么 |
|--------------|------------|------------|
| **逻辑闭环** | 准入要求：须具备含「模式切换、异常回滚、**空闲态归位**」的完整**《状态转移图》**；未达标技术侧可拒排期 | 具体缺口：如缺图、缺三要素之一、与 PRD 某锚点矛盾 → 矩阵行 + 必补（补图/补节点） |
| **路径完整** | 核心主流程须具备完整**交互/原型**（**进入、操作、报错、退出**四节点）；未达标可拒排期 | 缺哪类节点、哪条流程无覆盖 → 行级缺陷 |
| **规则裁决** | 多任务**优先级抢占**须提供**《优先级裁决矩阵表》**；未达标可拒排期 | 缺表、或表与文不一致、有冲突未决 → 行级缺陷 + 必补 |

- **L1**：在管理摘要中增加**独立小节**「项目启动红线（准入）」或与「限制开工」**触发条件**合并呈现。
- **L3**：可给缺口行加**标签/类型**（如 `准入-状态图`），便于与 L1 红线一一对应。
- **L2**：不承载红线**本体**；若 L2 某条澄清**承诺**补交某交付物，可**回链** L1 红线 + L3 id。
