## 1. 对本发明涉及的关键技术术语的说明

### 1.1 三段式审计流水线（3S：Structure / Scan / Summary）
指本发明中 PRD 审计的三阶段协同工作模式：  
- Structure（结构化解析）：将 PRD 原文解析为结构化需求模型（模块/流程/状态/事件/规则/依赖等）。  
- Scan（漏洞扫描）：基于“确定性规则引擎 + 大语言模型推理”进行混合检测，输出缺陷列表。  
- Summary（报告生成）：对缺陷进行标准化、合并聚类、风险量化与报告渲染，并支持多角色视角输出。

### 1.2 结构化需求模型（SystemModel / Requirement Model）
一种中间表示（IR），用于把非结构化的自然语言 PRD 转化为可计算的结构化数据。本发明中该模型至少包含：模块（modules）、流程（flows）、状态（states）、事件（events）以及状态转移（transitions）。可选包含：规则（rules）、高优先级事件（high_priority_events）、外部依赖（dependencies）、权限角色（roles）等。

### 1.3 规则-大模型混合引擎（Hybrid Audit Engine）
指将规则库/规则引擎的可解释、可重复优势，与大语言模型（LLM）的语义理解与推理优势进行融合的审计机制；两者输出经统一结构化、冲突消解与去重合并后形成最终缺陷集合。

### 1.4 上下文锚点（Context Anchor）
一种缺陷定位标准：对每条缺陷自动给出其在 PRD 原文中的定位信息（行号/段落/功能名），用于快速回溯与评审闭环。

### 1.5 噪音过滤机制（Noise Filtering）
一种规则适用性判断方法：根据 PRD 的结构化信息与全文特征，自动跳过不适用的规则类别，降低误报与报告噪音。

### 1.6 问题合并（Issue Merging）
一种缺陷聚类与去重策略：将多条相同类型/同源根因的问题归并为“核心问题”，输出合并版矩阵与原始清单，减少重复。

### 1.7 动态建议生成（Dynamic Suggestion）
基于“模块 + 问题类型 + 风险等级 + 描述要点”的组合，生成可执行的整改建议，避免固定模板导致的低质量建议。

### 1.8 七维质量评分（Seven-Dimension Quality Score）
对 PRD 的需求质量从多个维度进行量化评估，输出总体评分与等级，用于在研发流程中量化需求质量并驱动改进。

## 2. 技术背景
在软件研发过程中，PRD（产品需求文档）是研发、测试、产品协同的核心输入，但现有技术存在以下问题：

### 2.1 评审效率低
人工走读 PRD 耗时长，在多模块/多角色/多端的复杂需求中，评审成本呈线性乃至超线性上升。

### 2.2 漏洞隐蔽、易遗漏
复杂流程（尤其是状态机、多分支异常、并发冲突）难以仅靠人工直觉穷举覆盖，导致上线后出现严重缺陷（资损、越权、状态错乱、重复扣费、数据不一致等）。

### 2.3 结论不可复用、标准不一致
不同评审人输出不一致，缺陷描述不标准，难以沉淀为组织级资产与可追踪的质量度量体系。

### 2.4 难以定位与闭环
传统“评审意见”常缺少对应的原文定位，导致产研测对问题的理解不一致，整改闭环成本高。

### 2.5 单纯依赖大模型存在幻觉与不稳定
直接把 PRD 交给大模型输出“问题清单”存在幻觉、口径飘忽、结构不稳定、难以复核的问题，难以工程化落地到流程体系中。

## 3. 本发明技术方案详细说明

本发明提出一种 PRD 智能审计系统，通过“结构化状态模型 + 规则-大模型混合引擎 + 报告聚合”实现从“被动阅读”到“主动发现”的自动化审计，并可持续沉淀规则与经验。

### 3.1 核心程序模块构成
本发明可由以下程序模块实现（可部署于服务器/云端/本地）：

1）输入接入模块（ING）  
- 接收 PRD 原文、飞书链接、PDF/Word 等输入；完成文本抽取与规范化；保留原文用于锚点定位。

2）结构化解析模块（STR）  
- 将 PRD 文本解析为结构化模型：模块、流程、状态、事件、状态转移、规则要素等；  
- 输出统一的结构化 JSON 作为审计的中间表示。

3）规则库与规则执行模块（RUL）  
- 维护可配置的审计规则库；  
- 执行状态机完整性、流程闭环、并发冲突、异常覆盖、权限安全、数据契约等规则检测；  
- 支持噪音过滤（规则适用性判断）。

4）大模型审计模块（LLM-AUD）  
- 以结构化模型作为输入上下文，引导 LLM 对矛盾、歧义、缺失、风险等进行语义推理扫描；  
- 输出与规则引擎一致的结构化缺陷 JSON；要求未说明内容标记为“PRD未说明”。

5）缺陷标准化与融合模块（FUS）  
- 对来自规则与 LLM 的缺陷进行字段归一（风险等级、类型、模块、描述、原因、建议）；  
- 自动生成上下文锚点；  
- 合并重复问题并生成“核心问题矩阵”；  
- 对建议进行动态生成或改写，避免模板化。

6）报告生成与导出模块（REP）  
- 生成标准化审计报告（Markdown/Word）；  
- 输出核心风险摘要、合并版矩阵、原始缺陷清单、待确认清单、测试重点、研发重点、计划建议；  
- 可按角色输出裁剪版本（给产品/给研发/给测试）。

### 3.3 详细执行步骤

#### 步骤一：输入获取与文本规范化（ING）
a) 接收 PRD 输入（粘贴文本/飞书链接/PDF/Word）；  
b) 若为外部链接，自动拉取正文；若为文件，抽取文本；  
c) 对文本进行去噪与格式化（空白归一、段落切分等），并保留原始行号映射。

#### 步骤二：结构化解析（STR）
a) 识别 PRD 中的功能模块、业务流程、状态与事件；  
b) 抽取状态转移信息（from/event/to/condition），形成可计算的状态机模型；  
c) 输出结构化 JSON 作为下一阶段输入。

#### 步骤三：规则扫描与适用性过滤（RUL）
a) 根据结构化模型与全文特征计算规则适用性，对明显不相关的规则类别跳过；  
b) 对适用规则执行检测，得到规则缺陷集合（例如：状态×事件未定义、并发事件冲突、异常/边界缺失、权限缺失等）；  
c) 对规则缺陷进行初步归一（风险等级映射、字段补齐）。

#### 步骤四：大模型语义审计（LLM-AUD）
a) 将结构化模型与 PRD 原文摘要拼接为提示上下文；  
b) 约束大模型仅输出结构化缺陷 JSON，未说明内容必须标记“PRD未说明”；  
c) 得到语义缺陷集合（例如：逻辑矛盾、描述歧义、外部依赖风险、体验与流程风险、数据一致性风险等）。

#### 步骤五：缺陷融合、锚点定位与合并（FUS）
a) 对规则缺陷与大模型缺陷统一字段格式（风险等级归一、缺陷类型归一、模块归一）；  
b) 为每条缺陷生成上下文锚点：从 PRD 原文中定位到最相关的行或功能段落；  
c) 对建议字段进行动态生成或改写，使其与模块+类型一致且可执行；  
d) 进行问题合并：按缺陷类型/模块/语义相似度聚类，生成核心问题矩阵，并保留原始缺陷清单。

#### 步骤六：报告生成与导出（REP）
a) 计算七维质量评分与总体风险等级；  
b) 生成核心风险摘要（一句话总结 + Top3 致命风险）；  
c) 输出合并版矩阵、原始缺陷清单、待确认清单、测试重点、研发重点、计划建议；  
d) 支持导出 Markdown 与 Word，并可按角色裁剪报告内容。

## 4. 流程图（文字版）
PRD输入 → 文本抽取/规范化 → 结构化解析（模块/状态/事件/转移）  
→ 规则适用性过滤 → 规则扫描缺陷（确定性）  
→ LLM 语义扫描缺陷（推理）  
→ 缺陷融合归一 + 上下文锚点定位 + 问题合并  
→ 风险量化评分 + 核心摘要  
→ 报告渲染与导出（Markdown/Word/角色版）

## 5. 本发明的技术效果

### 5.1 显著提升审计效率
将长文档的人工预审转化为自动化流水线输出，评审准备时间从小时级降低至分钟级，且可批量并行处理。

### 5.2 明显降低漏检率
通过结构化状态模型与状态/事件覆盖检查，能够发现人工难以覆盖的流程断裂、状态不可达、并发冲突等深层问题。

### 5.3 报告更可执行、更可复核
每条缺陷具备上下文锚点定位与动态建议，降低沟通成本，提升整改闭环效率。

### 5.4 兼顾确定性与智能推理
规则引擎提供可解释性与稳定性，大模型提供语义理解与推理能力，两者融合降低幻觉与误报，提升整体可靠性。

### 5.5 可持续演进与资产沉淀
规则库与提示词可配置、可迭代，审计输出结构化可追踪，能够形成企业级需求质量治理资产。

## 7. 是否还有其他替代方案
存在若干替代方案，但效果明显弱于本发明：

1）纯人工评审：成本高、漏检率高、不可规模化。  
2）纯规则扫描：缺乏语义理解，对歧义、矛盾、隐性风险识别能力弱。  
3）纯大模型审计：输出不稳定、可解释性差、易幻觉，难以工程化落地到流程体系中。  
本发明通过“结构化模型 + 规则确定性 + LLM 语义推理 + 报告融合”的闭环机制，解决了以上方案的核心缺陷。
