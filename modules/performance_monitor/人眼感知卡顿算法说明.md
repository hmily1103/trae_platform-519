# 人眼感知卡顿算法设计说明

## 一、现状分析

### 1. 标准卡帧数据（Jank）- ✅ 已有实现

**位置**：`trae_platform/modules/log_monitor/core/adb_controller.py` 的 `_collect_fps_data()` 方法

**数据源**：`dumpsys gfxinfo <package_name>`

**判断标准**：
- 帧时间 > 16.67ms 算作 jank（60fps 标准）
- 统计总帧数和 jank 帧数

**返回数据**：
- `fps`：平均帧率
- `jank_count`：卡顿帧数量
- `frame_times_list`：详细的帧时间序列（新增）

**已集成**：数据存储在 `PerformanceSnapshot` 中

---

### 2. 人眼判断卡顿数据 - ⚠️ 部分实现，需要统一

**现有实现（分散）**：

1. **基于 Jank 百分比的简单判断**
   - 位置：`android_player_stress_test/core/monitor.py`
   - 逻辑：`is_perceptual_jank = (jank_percent > 15.0 and delta_total > 10)`
   - 问题：过于简单，不够精确

2. **基于截图间隔的卡顿评分**
   - 位置：`sanfang/video_stall_monitor_win.py`
   - 逻辑：计算相邻截图的时间间隔，使用 `stall_score` 累加卡顿权重
   - 优点：能反映实际画面更新延迟
   - 问题：仅基于截图间隔，未考虑画面内容变化

3. **基于画面静止检测**
   - 位置：`android_player_stress_test/core/image_analyzer.py`
   - 逻辑：间隔抓取截图，使用 PIL 计算图像差异
   - 问题：误报率较高，已部分禁用

4. **基于 Logcat 的卡顿日志**
   - 位置：`android_player_stress_test/core/log_monitor.py`
   - 检测模式：`Skipped frames`, `missed frames`, `droppedFrames`, `AudioTrack underrun` 等
   - 优点：能捕获播放器层面的卡顿
   - 问题：依赖日志输出，可能不完整

## 二、统一的人眼感知卡顿算法设计

### 1. 核心类：`PerceptualStallAnalyzer`

**位置**：`trae_platform/modules/performance_monitor/perceptual_stall_analyzer.py`

**算法原理**：

1. **基于帧时间序列分析**
   - 从 `dumpsys gfxinfo` 获取详细的帧时间序列
   - 检测帧时间突然增加（超过阈值）
   - 考虑连续多帧延迟（比单帧延迟更明显）

2. **加权评分算法**
   - 使用指数权重：`weight = pow(excess, 1.2)`
   - 严重卡顿（如50ms）的权重远高于轻微卡顿（如20ms）
   - 连续卡顿加成：连续3帧以上卡顿时，权重 × 1.3
   - 持续时间加成：长时间卡顿权重更高

3. **严重程度分级**
   - **轻微（mild）**：帧时间 > 25ms（1.5倍期望值）
   - **中等（moderate）**：帧时间 > 33.33ms（2倍期望值）
   - **严重（severe）**：帧时间 > 50ms（3倍期望值）

4. **卡顿事件检测**
   - 检测卡顿开始和结束
   - 记录卡顿持续时间、帧数、平均帧时间、最大帧时间
   - 生成卡顿事件描述

### 2. 数据模型扩展

**`PerformanceSnapshot` 新增字段**：

```python
perceptual_stall_score: float = 0.0  # 累计卡顿评分
perceptual_stall_events: int = 0  # 卡顿事件数
perceptual_stall_duration_ms: float = 0.0  # 总卡顿时长
is_perceptual_stalling: bool = False  # 当前是否在卡顿
perceptual_stall_severity: str = ""  # 当前卡顿严重程度：mild/moderate/severe
frame_time_variance: float = 0.0  # 帧时间方差（波动性）
```

### 3. 集成流程

1. **数据收集**：
   - `_collect_fps_data()` 返回帧时间序列
   - 存储在 `controller._cached_frame_times`

2. **分析处理**：
   - 在 `performance_callback` 中，将帧时间序列添加到 `PerceptualStallAnalyzer`
   - 分析器计算卡顿指标
   - 更新 `PerformanceSnapshot` 中的人眼感知卡顿数据

3. **数据存储**：
   - 快照存储到 `PerformanceStorage`
   - 支持历史查询和基线对比

4. **前端显示**：
   - 显示标准 Jank 数据
   - 显示人眼感知卡顿数据（评分、事件数、严重程度等）

## 三、两种数据的区别

### 标准卡帧数据（Jank）

- **定义**：帧时间超过 16.67ms（60fps 标准）
- **特点**：客观、精确、技术指标
- **用途**：性能优化、技术分析
- **数据**：`jank_count`（卡顿帧数）

### 人眼感知卡顿数据

- **定义**：基于帧时间序列，考虑连续性和严重程度的综合评分
- **特点**：更接近人眼感知、考虑实际体验
- **用途**：用户体验评估、卡顿严重程度判断
- **数据**：
  - `perceptual_stall_score`：累计卡顿评分
  - `perceptual_stall_events`：卡顿事件数
  - `perceptual_stall_duration_ms`：总卡顿时长
  - `is_perceptual_stalling`：当前是否在卡顿
  - `perceptual_stall_severity`：当前卡顿严重程度
  - `frame_time_variance`：帧时间方差（波动性）

---

## 四、算法优势

1. **更准确**：基于帧时间序列，而非简单统计
2. **更智能**：考虑连续卡顿和持续时间
3. **更实用**：严重程度分级，便于问题定位
4. **可扩展**：易于集成其他数据源（截图、日志等）

---

## 五、使用示例

```python
# 创建分析器
analyzer = PerceptualStallAnalyzer(target_fps=60, window_size=120)

# 添加帧时间数据
for frame_time_ms in frame_times_list:
    analyzer.add_frame_time(frame_time_ms)

# 获取当前指标
metrics = analyzer.get_current_metrics()
print(f"卡顿评分: {metrics.stall_score}")
print(f"卡顿事件数: {metrics.total_stall_events}")
print(f"当前是否卡顿: {metrics.is_stalling}")
print(f"严重程度: {metrics.severe_stalls} 次严重卡顿")
```

## 六、后续优化方向

1. **集成截图数据**：结合画面变化检测，提高准确性
2. **集成日志数据**：结合 logcat 卡顿日志，捕获播放器层面卡顿
3. **机器学习优化**：基于用户反馈，优化卡顿评分算法
4. **实时告警**：当检测到严重卡顿时，实时推送告警

---

## 七、注意事项

1. **性能影响**：帧时间序列分析会增加一些计算开销，但影响很小
2. **数据准确性**：依赖 `dumpsys gfxinfo` 的准确性，某些设备可能不支持
3. **阈值调整**：可根据实际应用场景调整阈值（mild/moderate/severe）
