# KTV播放器压测 - 快速开始指南

## 🚀 一键启动（推荐）

### Windows 用户

```batch
# 1. 复制配置文件模板
copy config.json.example config.json

# 2. 编辑 config.json，修改包名等参数
notepad config.json

# 3. 运行一键启动脚本
python run_ktv_test.py
```

### Linux/Mac 用户

```bash
# 1. 复制配置文件模板
cp config.json.example config.json

# 2. 编辑 config.json，修改包名等参数
nano config.json  # 或使用其他编辑器

# 3. 运行一键启动脚本
python3 run_ktv_test.py
```

## 📋 配置说明

### 1. 复制配置文件

```bash
# Windows
copy config.json.example config.json

# Linux/Mac
cp config.json.example config.json
```

### 2. 编辑 `config.json`

**必须修改的参数**：

```json
{
    "target_app": {
        "package_name": "你的播放器包名",  // 例如: "com.thunder.ktv:media"
        "main_activity": "你的主界面Activity"  // 可选
    },
    "test_strategy": {
        "mode": "monitor_only",  // monitor_only | fixed_skip | loop_playback
        "duration_minutes": 720,  // 测试时长（分钟），720分钟=12小时
        "skip_interval_seconds": 300  // 切歌间隔（秒），仅在fixed_skip和loop_playback模式下生效
    },
    "monitor": {
        "interval_seconds": 2  // 性能数据采集间隔（秒），建议1-2秒
    }
}
```

**可选参数**：

- `device_id`: 如果为 `null`，会自动选择第一个连接的设备
- `http_vod`: 如果使用 HTTP 点歌功能，需要配置服务器IP等信息

## 🔍 环境检查

运行 `run_ktv_test.py` 时，脚本会自动检查：

1. ✅ **ADB 环境** - 确保 ADB 已安装并添加到 PATH
2. ✅ **设备连接** - 确保设备已通过 USB 或网络 ADB 连接
3. ✅ **Root 权限** - 检查硬件解码监控是否可用
4. ✅ **Display 配置** - 自动检测电视端 Display ID（1 或 2）
5. ✅ **SurfaceFlinger** - 检查 FPS 获取是否可用
6. ✅ **配置文件** - 验证配置文件格式是否正确

## 📊 报告中的关键指标

测试结束后，在报告中重点关注以下指标：

### 🚨 电视端视频卡顿（最重要）

- **TV Video Stutter (电视端视频卡顿)**: 如果该项不为 0，说明电视画面出现了人眼可见的卡死
- **Decoder Stuck (解码器卡死)**: 如果该值增长，说明 RK 芯片硬件层已经停止输出了
- **TV Freeze (画面冻结)**: 通过 Display 1/2 截图对比发现的静止画面次数

### ⚠️ 其他指标（仅供参考）

- **UI Jank (点歌屏UI丢帧)**: 仅反映点歌屏UI线程负载，**不影响电视端视频质量**
- **Log Stutter (日志卡顿)**: 播放器内部报告的卡顿，非常准确

## 🐛 故障排查

### 问题1: 无法获取视频FPS

**症状**: 报告中显示"未能获取到视频帧率数据"

**调试步骤**:

1. 在播放视频时运行以下命令：
```bash
adb shell dumpsys SurfaceFlinger --display-id 1 --list
```

2. 将输出内容保存，可能需要调整 `monitor.py` 中的 Surface 过滤关键字

3. 检查输出中是否包含以下关键字：
   - `SecondaryDisplay`
   - `ExternalDisplay`
   - `HDMI`
   - `TV`
   - `SurfaceView`
   - `TextureView`

### 问题2: 硬件解码监控不可用

**症状**: Root 权限检查失败

**解决方案**:

1. 确保设备已开启 Root 权限
2. 测试 Root 权限：
```bash
adb shell "su -c 'id'"
```
应该返回 `uid=0`

3. 检查 MPP 节点：
```bash
adb shell "su -c 'ls /sys/kernel/debug/mpp_service/stats'"
```

### 问题3: 无法检测到电视端 Display

**症状**: Display 检测失败

**解决方案**:

1. 手动检查 Display 配置：
```bash
adb shell "dumpsys display | grep -i 'Display id='"
```

2. 如果检测到 Display 2 而不是 Display 1，系统会自动适配

3. 如果仍然失败，可以在代码中手动指定 Display ID

## 📝 使用示例

### 示例1: 纯监控模式（推荐）

```json
{
    "test_strategy": {
        "mode": "monitor_only",
        "duration_minutes": 720
    }
```

```json
{

        "mode": "loop_playback",
        "duration_minutes": 60,
        "skip_interval_seconds": 300
    }
}
```

**说明**: 每 5 分钟自动切歌，适合长时间稳定性测试

## 💡 调试小贴士

### 查看实时日志

运行 `run_ktv_test.py` 时，所有日志会实时输出到控制台，包括：
- 性能数据采集
- 卡顿检测结果
- 画面冻结警告
- 解码器卡死警告

### 查看报告

测试结束后，报告保存在 `reports/` 目录（或配置文件中指定的目录），包括：
- `summary_YYYYMMDD_HHMMSS.txt` - 文本报告
- `summary_YYYYMMDD_HHMMSS.json` - JSON 数据
- `report_YYYYMMDD_HHMMSS.csv` - CSV 数据

### 手动测试 SurfaceFlinger

如果无法获取视频 FPS，可以手动测试：

```bash
# 1. 查看所有 Surface
adb shell dumpsys SurfaceFlinger --list

# 2. 查看特定 Display 的 Surface
adb shell dumpsys SurfaceFlinger --display-id 1 --list

# 3. 查看特定 Surface 的延迟数据
adb shell dumpsys SurfaceFlinger --latency <SurfaceName>
```

将输出内容提供给开发者，可以优化 Surface 过滤逻辑。
