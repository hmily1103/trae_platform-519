# 纯监控模式 - 播放歌曲数检测配置说明

在**纯监控模式**下，系统默认通过 `dumpsys media_session` 获取当前播放的歌曲信息。若您的应用**未使用 Android MediaSession API** 或**未设置 metadata**，则无法自动统计播放歌曲数。

此时可通过配置 **Logcat 切歌关键字**，让系统在检测到特定日志时计为一次切歌。

---

## 如何找到合适的关键字

### 1. 使用 adb logcat 观察切歌时的日志

```bash
adb logcat -v time | tee logcat.txt
```

在设备上**手动切歌**，观察 logcat 输出中**每首新歌开始播放时**会出现的日志。

### 2. 常见关键字示例

| 应用类型 | 可能的关键字 | 说明 |
|---------|-------------|------|
| ExoPlayer | `onPrepared`, `prepareAsync`, `msg=2(STARTED)` | 播放器准备/开始 |
| MediaPlayer | `onPrepared`, `start()` | 标准 MediaPlayer |
| IjkPlayer | `av_get_frame_hold`, `prepareAsync` | IjkPlayer 引擎 |
| 自研播放器 | 需自行观察 | 如 `playSong`, `loadTrack`, `songId=` |
| KTV 应用 | `开始播放`, `切歌`, `songId=` | 业务层日志 |

### 3. 选择关键字的原则

- **每首新歌只出现一次**：避免同一首歌被重复计数
- **切歌时必定出现**：确保不漏计
- **尽量具体**：如 `songId=123` 比 `song` 更精确

### 4. 配置方式

在 Web 界面选择**纯监控模式**后，会显示「切歌检测关键字」输入框：

- 输入**逗号分隔**的关键字，如：`playSong, onTrackChanged, songId=`
- 支持**正则表达式**，如：`songId=\d+` 表示匹配 `songId=数字`
- 匹配到任意一个关键字即计为一次切歌（3 秒内去重，避免重复计数）

---

## 示例

### 示例 1：简单关键字

若切歌时 logcat 出现：
```
I/Player: 开始播放歌曲: 月亮代表我的心
```

可配置关键字：`开始播放歌曲`

### 示例 2：多个备选

若不同场景下日志不同：
- 首次播放：`onPrepared`
- 切歌：`onTrackChanged`

可配置：`onPrepared, onTrackChanged`

### 示例 3：正则匹配

若日志格式为 `loadSong id=1001`：
可配置：`loadSong id=\d+`

---

## 注意事项

1. **关键字需在切歌时出现**：若配置的是「播放中」的周期性日志，会导致计数过多
2. **3 秒去重**：同一关键字 3 秒内只计一次，避免单次切歌触发多条日志时重复计数
3. **无配置时**：仍会尝试 `dumpsys media_session`，若应用支持 MediaSession 则无需配置
