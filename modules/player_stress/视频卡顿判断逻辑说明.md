# 视频播放卡顿判断逻辑说明

## 一、判断维度（三个指标）

### 1. **视频画面帧率 (Video FPS)** - 最重要指标 ⭐⭐⭐
- **数据来源**: `dumpsys gfxinfo <package_name>` 或 `dumpsys SurfaceFlinger --latency`
- **获取方式**: 
  - 优先使用 `gfxinfo` 解析帧时间数据计算FPS
  - 备用 `SurfaceFlinger` 获取硬件层帧率
- **判断标准**:
  ```
  FPS < 15  → [严重警告] 视频帧率严重偏低，存在明显卡顿！
  FPS < 20  → [警告] 视频帧率偏低，可能存在卡顿
  FPS < 24  → [注意] 视频帧率略低于标准（24/25/30fps）
  FPS ≥ 24  → [良好] 视频帧率正常
  ```
- **说明**: 这是最直接反映视频播放流畅度的指标

### 2. **卡顿日志 (Log Stutter)** - 关键指标 ⭐⭐
- **数据来源**: `logcat` 实时监控
- **检测关键字** (正则表达式):
  ```python
  r"droppedFrames"           # ExoPlayer/IjkPlayer 丢帧
  r"underrun"                # 缓冲区下溢
  r"buffer starvation"       # 缓冲区饥饿
  r"AudioTrack.*underrun"    # 音频轨道下溢（强烈卡顿信号）
  r"AudioFlinger.*underrun"  # 音频混音器下溢
  ```
- **判断标准**:
  - 累计检测到 **> 5次** 卡顿日志 → 判定为视频播放卡顿
  - 每次检测到关键字，计数器 +1
- **说明**: 这是播放器内部报告的卡顿，非常准确

### 3. **界面交互流畅度 (UI Jank)** - 仅供参考 ⭐
- **数据来源**: `dumpsys gfxinfo` 中的 Jank 帧统计
- **计算方式**:
  ```
  Jank率 = (Jank帧数 / 总帧数) × 100%
  ```
- **判断标准**:
  - Jank率 > 20% 且 无日志卡顿 → 可能是UI渲染问题，不影响视频播放
- **说明**: 
  - 此指标反映UI线程负载
  - 全屏播放且无操作时，高丢帧率通常为误报
  - **不作为视频卡顿的主要判断依据**

## 二、智能分析逻辑

### 最终判断规则（优先级从高到低）:

```python
if (log_stutter > 5) or (video_fps > 0 and video_fps < 15):
    # 情况1: 视频播放卡顿 (Video Stutter)
    # 依据: 日志中有丢帧记录 或 硬件帧率过低
    result = "检测到视频播放卡顿"
    
elif (avg_jank > 20.0) and (log_stutter == 0):
    # 情况2: UI渲染丢帧 (UI Jank)，但不影响视频播放
    # 依据: GFX丢帧高但日志无异常，且视频帧率正常或未知
    result = "UI渲染丢帧，但不影响视频播放"
    
else:
    # 情况3: 播放流畅度整体良好
    result = "播放流畅度整体良好"
```

### 判断流程图:

```
开始判断
  ↓
是否有日志卡顿？(log_stutter > 5)
  ├─ 是 → [视频播放卡顿] ✅ 判定
  └─ 否 ↓
视频FPS是否可用？(video_fps > 0)
  ├─ 是 → FPS < 15?
  │        ├─ 是 → [视频播放卡顿] ✅ 判定
  │        └─ 否 ↓
  └─ 否 ↓
UI Jank率 > 20% 且 无日志卡顿？
  ├─ 是 → [UI渲染丢帧，但不影响视频播放] ⚠️
  └─ 否 → [播放流畅度整体良好] ✅
```

## 三、数据采集频率

### 1. 视频FPS采集
- **频率**: 每次快照采集时（默认每2秒）
- **缓存**: 2秒内复用结果，避免频繁ADB调用
- **超时**: 3秒（避免阻塞）

### 2. 日志卡顿检测
- **频率**: 实时监控 `logcat` 流
- **方式**: 正则表达式匹配关键字
- **累计**: 整个测试过程中累计计数

### 3. UI Jank统计
- **频率**: 每次快照采集时
- **方式**: `dumpsys gfxinfo` 获取增量Jank帧数
- **计算**: 增量Jank / 增量总帧数

## 四、阈值说明

### 为什么选择这些阈值？

1. **FPS < 15**: 
   - 标准视频帧率通常是 24/25/30fps
   - 15fps 约为标准帧率的 50-60%，明显低于人眼感知的流畅阈值
   - 低于此值，用户会明显感受到卡顿

2. **FPS < 20**:
   - 20fps 约为标准帧率的 67-83%
   - 可能存在轻微卡顿，但不如 <15fps 严重

3. **FPS < 24**:
   - 24fps 是电影标准帧率
   - 略低于此值可能影响流畅度，但不一定明显

4. **日志卡顿 > 5次**:
   - 播放器内部报告的卡顿非常准确
   - 5次是一个经验阈值，表示卡顿已经明显影响体验

5. **UI Jank > 20%**:
   - 20% 的丢帧率在UI交互中已经比较明显
   - 但如果视频FPS正常，说明只是UI渲染问题，不影响视频播放

## 五、实际应用示例

### 示例1: 视频播放卡顿
```
视频FPS: 12.5 FPS (< 15)
日志卡顿: 8次 (> 5)
UI Jank: 15%

判断结果: [视频播放卡顿]
依据: 视频帧率严重偏低 + 日志中有丢帧记录
```

### 示例2: UI渲染问题（不影响视频）
```
视频FPS: 28.5 FPS (正常)
日志卡顿: 0次
UI Jank: 35% (> 20%)

判断结果: [UI渲染丢帧，但不影响视频播放]
依据: GFX丢帧高但日志无异常，且视频帧率正常
```

### 示例3: 播放流畅
```
视频FPS: 29.8 FPS (正常)
日志卡顿: 0次
UI Jank: 5%

判断结果: [播放流畅度整体良好]
```

### 示例4: 无法获取FPS
```
视频FPS: 0 (无法获取)
日志卡顿: 3次 (< 5)
UI Jank: 10%

判断结果: [播放流畅度整体良好]
说明: 由于无法获取FPS，主要依赖日志卡顿判断
      如果日志卡顿 > 5，仍会判定为卡顿
```

## 六、注意事项

1. **视频FPS获取失败**:
   - 可能原因：应用未启动、gfxinfo数据不可用、设备不支持
   - 建议：参考日志卡顿分析作为替代指标

2. **UI Jank误报**:
   - 全屏播放且无操作时，UI线程可能不活跃
   - 高丢帧率可能是正常的，不作为视频卡顿依据

3. **日志卡顿最准确**:
   - 播放器内部报告的卡顿是最准确的
   - 即使FPS正常，如果日志中有卡顿记录，仍应判定为卡顿

4. **综合判断**:
   - 优先使用视频FPS和日志卡顿
   - UI Jank仅作为参考，不单独作为视频卡顿依据
